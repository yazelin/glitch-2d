# 格莉奇 2D

格莉奇自己的 2D 角色原型，可切換全身與聊天近景。重新生成的角色部件由原生 JavaScript 組合，使用 WebGL 繪製、Web Audio 帶動嘴型，沒有 Live2D、Cubism 或 Pixi 的執行期依賴。

## 0.5.0：單手揮手改走關節，表情部件可切換

### 掌心朝外的手做出來了

揮起來是**掌心正對鏡頭、五指張開**的手。這是整條線最初要解決的問題，先前幾版揮的都是手背。

旋轉變不出掌心，這是 Live2D 也用差分圖解決的那一類，所以走的是同一條路：袖子的貼圖換成拿掉手的版本，手獨立成兩個部件放在同一個 `leftHand` slot，`armFold` 過 0.55 時從側手掌換成正面掌心，任何時刻只有一隻手存在。手畫在袖子**底下**，腕端往下延長一段藏進袖口，所以看起來是從袖子裡伸出來的。

切換點在 t=0.40（上去）與 t=2.47（下來），都落在手臂還在途中的低角度，那個角度本來就該是側手掌。硬切沒有淡入，跟 Live2D 的切換式一樣；逐格看得出來手在那一格變大變正，動起來是否察覺得到還沒有人判定過。

素材是生成的，形狀對著 `pet-plain.webp` 的正典重繪，線色量過與袖子對齊（`151,79,78` 對 `129,86,94`）。位置、角度與大小由使用者在對齊工具裡調定。

### 揮手不再只是把整支袖子轉四度

先前的 `wave()` 是繞肩節點轉 `pose.arm * 0.07`，大約四度。這一版改成在 `deformPoint` 裡做兩段骨的蒙皮，吃的是 `rig.json` 早就寫好、但一直沒有人用的 `joints`（肩、肘、腕）座標。垂手的 `sleeve-left-v8.png` 一張都沒有重畫。

兩個驅動值：`armRaise` 乘上 `bend.shoulder` 帶肩，`armFold` 乘上 `bend.elbow` 帶肘。手腕沿用既有的 `hand` 設定，新增 `hand.wave` 權重接上 `pose.handAngle`。

動作照三條動畫原則寫：

**overlapping action。** 衝量沿著肢體往外傳，肩先動、肘落後 0.13 秒、手腕再落後一個相位。鏈上沒有任何一節跟父節點同時到位。

**follow-through。** 手臂抵達最高點時疊一段阻尼正弦，峰值衝到 1.05 再收斂。

**次要動作落後主要動作。** 眉毛與眼睛吃同一條曲線延遲 0.15 秒的版本。

依據是[動畫十二原則的 follow-through 與 overlapping action](https://www.animationmentor.com/blog/follow-through-and-overlapping-action-the-12-basic-principles-of-animation/)。

### 身體只做一件事：繞腰的一段小弧

`rig.json` 多了一個 `waist` 節點，樞紐在角色座標 y=1180，夾在 `body` 與上半身之間：

```
body（樞紐在腳底）
└── waist（樞紐在腰）   ← 身體的傾斜只掛在這裡
    ├── head
    ├── arm-left / arm-right
    └── 軀幹
裙子與雙腿留在 body，不跟著轉
```

上半身連同兩隻手當成一塊繞腰轉 **0.96 度**，頭因此移動約 13 像素。腰是樞紐所以位移為零，裙頭與軀幹底緣不會錯開；腿完全不動。

依據是 [Live2D 的 Adding Body Movement](https://docs.live2d.com/en/cubism-editor-tutorials/deformer/)：**身體的傾斜要做成弧線，不是側向平移**，而且腳不能離地。

其餘部位刻意不動：另一隻手、頭自己的旋轉、頭的平移全部是 0，而且測試鎖住。依據是 [Live2D 的 Motion Quality Improvement Tips](https://docs.live2d.com/en/cubism-editor-tutorials/motion-hint/)：**keep unnecessary parts stationary while others move**。同時動太多部位，讀起來就是扭。

頭髮四個部件的 `sway` 是 32 / 42 / 10（後髮、側髮、瀏海），驅動它的 `pose.hair` 是彈簧，所以頭停了頭髮還會晃一下。它吃的是**頭實際轉了幾弧度**，不是某個原始參數 — 早先那樣接會讓頭沒歪但頭髮狂甩。

### 上臂能動的範圍是量出來的，兩端都有牆

| 方向 | 界線 | 越界會怎樣 | 守門的檢查 |
| --- | --- | --- | --- |
| 往內收 | 不得小於 0 | 上臂沉進身體 | 手臂可見度掉到垂手水準以下就失敗 |
| 往外抬 | **0.12 到 0.17 之間** | 帽T 的袖根 socket 露出來 | socket 區域的破口比垂手時多就失敗 |

往外那道牆的由來：帽T 的貼圖本來畫著一塊袖根，`textures.torso.clearPolygons` 把它挖掉，讓衣袖接在上衣後方。那塊洞平常被袖子蓋著，上臂一抬過頭就露出來。不挖它也不行，垂手時兩肩會各多一塊深色橢圓。要抬更開得替帽T 補畫腋下，做法記在 `NEXT.md`。

現在用的是 `{shoulder: 0.12, elbow: 2.12}`。上臂只轉七度，高度靠肘。

負控制做過：把肩角開到 0.45，socket 的破口從 882 像素跳到 2236，檢查確實會失敗。

### 走錯的六條路

這一版的每個數字幾乎都是推翻前一個版本得來的，記下來免得再走一次。

1. **肩角 −0.1 加 `armTuck` 補償。** 抬手途中把上臂往身體裡壓，理由是前臂掃過水平時手掌會出框。結果上臂先擠進身體、前臂才伸出來，跟真人相反。當時的檢查器只量手掌，**沒量過上臂會不會被身體吃掉**。補上那條檢查之後，上臂在 0.23 秒只剩 24% 露在外面，垂手時是 92%。
2. **肩角 0.55 讓上臂正常外展。** 順序仍是肩先抬，手臂會先打直往外伸，75 格被取景切掉。
3. **改成肘領先。** 切邊解決了，但動畫原則是肩先動、肘落後，這是為了遷就取景把因果顛倒。
4. **軀幹剪切（`SPINE_SHIFT`）。** 軀幹那張圖是從脖子到髖的一整片，沿高度剪切就是把它拉斜，兩個端點剛好是它跟頭與裙子的交界，所以脖子與髖同時讀成扭。
5. **繞腳底旋轉 1.4 度。** 是弧線，但幅度太大，整個人在晃。
6. **身體完全靜止。** 扭是沒有了，但讀起來像機械。

第 1 條還留下一個看不見的副作用：手臂節點跟著傾斜往身體方向位移 39 像素，**那個位移一直在遮袖根的洞**。所以第 4、5 條拆掉之後外展上限要重量 — 先前記的 0.25 是在有遮擋的情況下量的。

### 取景加寬了

`views.full` 從 `[-160,0,1320,2470]` 改成 `[-380,0,1462,2470]`，`views.bust` 同步。寬度是量出來的：揮手時角色實際佔到的最左點加上餘裕。原本的取景右邊有 118 像素是空的，所以有一部分是往左挪、不是純加寬。

代價是同一個容器裡角色小一圈。站上桌寵的畫布是 855×1600，原本的取景長寬比跟它剛好吻合，縮放是 0.648；改寬之後是 0.585，角色變成原本的 90%。垂手時左邊那塊空間是留給揮手的，所以靜止時格莉奇會稍微偏右。

### 揮手是量出來的，但量的是骨架不是觀感

`node tools/check-wave.mjs` 每一格渲染三次（完整畫面、拿掉左手臂、只有左手臂），用像素差算出手掌與整條手臂有多少留在畫面上，並檢查有沒有被取景切掉、袖根的洞有沒有露出來、脖子有沒有被拉長、軀幹有沒有隨每一次揮動來回擺。六條檢查全部跑完才決定結束碼。加 `--frames` 會把逐格 PNG 寫進 `test-results/wave/`。

**待機是開著跑的。** 早先為了量測可重現把待機關掉，結果量出來的數字比較好看，而渲染出來的影片呈現一種出貨時不存在的僵硬。

| 量到的 | 值 |
| --- | --- |
| 靜止時手掌頂端 | 角色座標 y=1196 |
| 最高點 | y=459，比肩點（y=630）高 171 像素 |
| 手掌可見度最低點 | 100%，全程沒有被遮過 |
| 上臂可見度 | 靜止 92%，全程最低也是 92% |
| 袖根破口 | 靜止 857 像素，最差 940 |
| 脖子伸長 | 1% |
| 舉手期間軀幹反向 | 0 次 |
| 手掌離取景左緣最近 | 76 像素 |
| 被取景切掉的格數 | 0 |

這些全部是「骨架有沒有動對」。**沒有一條在量「像不像打招呼」**，而那正是這件事最初要解決的問題。

`npm run test:runtime` 另外在 WebGL 與 Canvas 兩條路徑上斷言揮手會到頂、會回到原位、前臂至少反向三次、肩在上去時領先肘、抵達時有過衝、該靜的部位全程是 0、身體有一段小弧。

### 量靜態差異用平均，量動態幅度要逐幀

會動的東西不能用時間平均去量。抖動、擺動、過衝這類訊號是零均值的，平均之後互相抵消，抖得越兇平均越說「什麼都沒發生」。正確的做法是逐幀各自比對，再取極值、反轉次數或行程。

`tools/check-expression.mjs` 把這件事量出來了。它在出貨尺寸（220 像素高）下渲染每個表情 90 格，每一格各自跟平常臉相減：

| 表情 | 逐幀最強 | 時間平均 | 平均低估 |
| --- | --- | --- | --- |
| happy | 15.3 | 13.2 | 13% |
| thinking | 33.7 | 31.9 | 5% |
| sleep | 33.5 | 31.2 | 7% |
| **error** | **62.6** | **43.2** | **31%** |

error 是唯一一個會逐幀抖動的表情（呼叫端每幀給頭部隨機位移），也是唯一一個被平均嚴重低估的。靜態的三個差距都在 13% 以內，那是待機呼吸造成的。

同一支工具也量出畫上去的眼睛有多少幫助：happy 從 14.1 到 15.3、error 從 59.4 到 62.6。

`tools/check-wave.mjs` 的六條檢查沒有這個問題，而且是結構性的沒有 — 每一條都是逐幀算完取極值（切邊取最大、可見度取最小、袖根破口取最大、脖子取最大、肩身偏移取絕對值最大），軀幹扭動那條更直接是逐幀差分數反轉次數，那正是平均會歸零的東西。

還有一個殘留的侷限要記著：整個畫面相減時，數字會被「頭移動了多少」主導，轉頭的表情因此虛高、只改眼睛嘴巴的表情虛低。加上臉部視窗改善了，但沒有完全隔離。要真的只量五官，得先把頭的姿勢歸零再比。

### 肘部的像素裝飾會被拉糊，這個修不掉

袖子上那幾塊像素裝飾與斜向的粗紋，貼在肘關節的部分會隨著彎曲被拖成一道細痕。調 `bend.blend` 沒有用：收到 0.18 會把肘折出硬摺痕，放到 0.45 會在肘中央撕開一個洞。真正的解法是照 Live2D 把袖子切成上臂與前臂兩片、在關節處各自補畫重疊區，那是改素材。

桌寵只有 220 像素高，那道細痕在該尺寸下約兩到三個像素，混在袖子的陰影裡。先留著。

### 對齊工具認得模型自己的欄位

`bend`、`hand`、`slot`、`variant`、`sway`、`views`、節點階層與部件掛在哪個節點下，都是模型自己的屬性，不是使用者的對齊。校正檔擁有的是它的 `adjustment`，以及那個位置所相對的幾何（`rect`／`uv`／`texture`／`mesh`）；其餘一律由模型供應。

這條規則是倒著寫的，因為原本逐一列出模型欄位的做法，讓每加一個 rig 功能就把所有舊設定拒收一次，這一版踩了四次。中間一度倒過頭連 `rect` 也蓋掉，防呆整個失效，被兩個既有測試抓回來。

順帶修掉一個潛伏的問題：判斷素材群組有沒有換過用的是普通的 `JSON.stringify`，物件的鍵只要換個插入順序就會被當成不同的素材，使用者的調整會被整片丟掉。改成跟旁邊的底模比對共用同一個排序過的序列化器。

### 表情部件可以整組換掉

`rig.json` 的部件多了 `slot` 與 `variant`。同一個 `slot` 裡一次只顯示一個 `variant`，由 `pose.slots` 指定，沒有指定就顯示 `default`。目前只有 `eyes` 這一組，現有的眼白、虹膜與閉眼線都標成 `default`，行為和以前一樣；之後補上畫好的笑眼或螺旋眼，只要在圖集裡多一個 `variant` 就能換。

桌寵用的那套表情參數本來只存在 `ai-brain-site/glitch2d/pet.js`，改一邊會忘記另一邊。現在 `EMOTES`、`GLITCHED_EMOTES` 與 `NEUTRAL_POSE` 都移到 `engine/motion.js`，跟著 `sync_glitch2d.py` 一起同步過去。展示頁那組 `EXPRESSIONS` 是給滿版臉用的微表情，幅度差一個量級，維持獨立，五顆表情鈕的行為沒有變。

`textures.crop` 在載入時擷取來源區域，`clearRects` 排除圖集裡相鄰部件的邊角，`clearPolygons` 遮去上衣原先畫出的袖口接合洞，讓衣袖接在上衣後方。這些都是載入時的遮罩，沒有覆寫原始圖片。`rect` 使用角色座標，`uv` 使用擷取後的圖片座標；有 `lockAspect` 的部件會在驗證時檢查來源比例。前版 `body-hair.png` 仍保留，但新版不再載入。

衣袖的 `hand` 設定使用相對於部件的手腕座標，僅調整手掌區域。腿部 `attachment.depth` 與 `attachment.extend` 是部件高度的比例，控制裙子底下的遮蓋區域，縮放部件時會一起更新；膝蓋、配件與鞋底不受此延伸影響。`reference` 固定參考圖在角色座標中的位置，供離線疊圖工具使用。

## 之後接 AI 語音

等角色載入後，可以從同頁的控制程式操作：

```js
const glitch = await window.Glitch2D.ready;
glitch.setExpression('happy');
glitch.setIdle(true);
glitch.setView('bust'); // 'full' also available
glitch.setParameters({ headZ: 0.2, gazeX: -0.3 });
await glitch.playAudio('/voice/reply.mp3');
// playAudio resolves when playback starts. Audio drives mouth until ended/stopped.
// Cross-origin audio must allow CORS for Web Audio analysis.
```

| 介面 | 行為 |
| --- | --- |
| `setExpression(name)` | 支援 `neutral`、`happy`、`curious`、`sleepy`、`shy` |
| `setParameters(values)` | 設定頭部、視線、眼睛、嘴巴、眉毛等參數；自動限制範圍 |
| `setIdle(boolean)`、`setFollow(boolean)` | 開關自然待機與游標跟隨 |
| `setView(name)` | `full` 顯示全身，`bust` 顯示聊天近景；同步更新分享網址 |
| `blink()`、`gesture()` | 執行短暫眨眼或招呼動作 |
| `playAudio(url)`、`stopAudio()` | 播放語音並帶動嘴型，或停止播放並閉嘴 |
| `getParameters()`、`getInfo()` | 取得目前參數與繪製狀態 |
| `exportRig()` | 取得角色設定的獨立副本 |

瀏覽器首次播放聲音通常需要使用者操作。這個介面在目前頁面內使用；透明舞台是獨立頁面，尚未提供跨視窗或 OBS 的遠端控制通道。

後續可依序接上「挑選留言、生成回覆、合成語音、播放並設定表情」。帳號授權與服務金鑰應放在本機服務或後端。專屬編輯器則可沿用同一份角色格式與引擎，逐步加入部件上傳、轉動中心、遮罩和動作關鍵格。

## 本機執行與驗證

需要 Node.js 22。單純展示可用任意靜態 HTTP 伺服器，不需打包。

```sh
npm install
npm run dev
# http://127.0.0.1:4177/
npm test
npm run build
npm run render
npm run compare
npm run test:runtime
npm run test:alignment
```

- `npm test`：檢查參數限制、眨眼幾何、視線遮罩、音量嘴型、彈性運動、父子節點與極端參數。
- `npm run build`：檢查 JS 語法、圖集尺寸、UV、網格、網站連結與本機依賴；GitHub Pages 直接使用原始檔，不另產生打包目錄。
- `npm run render`：用相同網格產生全身、近景、眨眼、表情、轉頭及手臂擺動等十二個狀態的透明 PNG，存入忽略提交的 `test-results/`，供檢查接縫與表情。
- `npm run compare`：產生相同尺度的三欄疊圖，存入 `test-results/turnaround-alignment.png`。確認完成後，可用 `npm run compare -- --publish` 更新目前版本的公開對照圖。
- `npm run test:runtime`：啟動臨時伺服器，驗證 Chromium 中的 WebGL 與 Canvas 程式介面、語音嘴型、播放停止及資源載入。首次使用若缺少 Chromium，執行 `npx playwright install chromium`。此檢查不截圖、不操作控制面板，也不代表完成手動外觀驗收。
- `node tools/check-expression.mjs`：在出貨尺寸下逐幀量每個表情跟平常臉的差距，並列出時間平均以顯示平均法低估了多少。
- `node tools/check-wave.mjs`：在渲染出來的像素上量揮手，回報手掌的可見比例、最高點與橫向行程，手掌被遮住超過四分之一或有東西被取景切掉就以非零結束。加 `--frames` 會另外把逐格 PNG 寫進 `test-results/wave/`。
- `npm run test:alignment`：透過程式介面驗證小工具的載入、移動、旋轉、縮放、部件開關、骨架開關、取景、復原與設定往返；同時確認底圖位置保持固定。

比例工具匯出的 `parts[].adjustment` 是部件的額外仿射變換，套用在網格變形後、父節點變換前，眼眶遮罩也使用相同變換。原始素材、UV 與部件設定保持不變，因此匯出檔可直接供展示頁讀取。載入設定時會核對底模。已知的衣袖、裙子、腿部更新會套用新版素材及初始比例，頸部與下巴使用新版局部修正，其餘調整會保留；不相容的其他部件結構仍會拒絕載入。

`?renderer=canvas` 可強制使用 Canvas 備援；效能會依裝置與畫面大小而異。`?overlay=1` 隱藏操作介面，保留透明角色畫面。`?view=bust` 顯示聊天近景，省略時預設全身。

GitHub Pages 延用 `main` 分支根目錄，保留 `.nojekyll`。先前的 Live2D 頁面移至 `legacy/`，其 `model/` 與 `source/` 仍在原位置；新版不會讀取這些檔案。原有 Cubism 專案與 PSD 保留。
